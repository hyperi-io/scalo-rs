# Migrations: 2.14.45

API and behaviour changes in 2.14.45 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## A Kafka sender stays ready while another topic delivers (BEHAVIOUR CHANGE)

One missing destination topic used to fail the whole Kafka sender's health. Now `is_healthy()` stays true and the `transport:kafka` check reports `Degraded`, which readiness counts as ready, while some destinations are missing and another delivers. It fails only when every destination the sender has written to is missing. `KafkaTransport::missing_destinations()` lists the missing topics.

**Consumer adjustment** -- none for a single-topic sender. An app that gates on `is_healthy()` for a multi-topic sender keeps sending to the topics that exist. It can check `missing_destinations()` to gate per topic.

## A gRPC listener limits queued bytes, streams and requests (BEHAVIOUR CHANGE)

A `listen` server now holds at most `max_queued_bytes` (64 MiB) of payload in its receive queue. It allows `max_concurrent_streams` (64) streams and `max_requests_per_connection` (64) requests at once per connection, and PINGs idle connections. A push past the byte budget answers `ResourceExhausted`, or `Unavailable` for a Vector push, which senders retry.

**Consumer adjustment** -- none for most apps. A receiver that takes many large `RouteBatch` requests faster than it reads them sees backpressure sooner. It raises `max_queued_bytes`, or sets it to `0` for the old behaviour.
