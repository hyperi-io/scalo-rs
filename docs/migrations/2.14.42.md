# Migrations: 2.14.42

API and behaviour changes in 2.14.42 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## scalo-service spreads pods across nodes by default (BEHAVIOUR CHANGE)

With `affinity` unset, a workload that can run more than one pod renders a preferred pod anti-affinity on `kubernetes.io/hostname`, weight 100, over the selector labels. More than one pod means a `replicaCount` above 1, KEDA on, or the fallback HPA on. A singleton and a single fixed replica render none. Preferred, so a single-node cluster still schedules every replica.

**Consumer adjustment** -- none for most apps: the next rebuild renders the default. A deployer that wants no anti-affinity sets `affinity` to any other non-empty value, which replaces the default outright. A chart that silenced kube-linter's `no-anti-affinity` check can drop the annotation.

## A release window receives the start budget (BEHAVIOUR CHANGE)

While the memory latch holds, the byte budget sits at its floor, 1 KiB by default. A hold that reaches `max_hold_secs` opens a release window, and its receives were sized by that floor, so a window admitted about 4 records. `ByteBudgetController::byte_budget()` now returns at least the profile's start budget from the moment the hold is due until a receive returns records. The stored budget still shrinks as held, and the `self_regulation_byte_budget` gauge reports it.

**Consumer adjustment** -- none. A consumer held above `pause_above` drains one start-budget block per `max_hold_secs`, where it drained about 4 records. A memory limit sized with no headroom for one block per window needs that headroom.

## Push listener TLS: `listen_tls` (API CHANGE)

`GrpcConfig` has a new public field, `listen_tls: Option<ServerTlsConfig>`, which serves TLS on the `listen` address with ALPN `h2`. Unset, the listener serves plaintext as before. Setting `listen` without `listen_tls` in a production deployment logs one warning at bind.

**Consumer adjustment** -- a `GrpcConfig` struct literal ends in `..Default::default()` (or `..GrpcConfig::server(..)`). An existing listener keeps serving plaintext until `listen_tls` is set.

## A drain has a deadline, and a second signal exits (BEHAVIOUR CHANGE)

A service still draining `shutdown.drain_deadline_secs` after the first SIGTERM or SIGINT logs one WARN line with `held_records` and `held_bytes`, flushes telemetry and exits with status 0. A second SIGTERM or Ctrl-C logs the WARN line and exits at once, without the telemetry flush. Neither exit releases what is held, so the source delivers those records again. The default is the contract's `termination_grace_seconds` less 10 s, 35 s with no contract.

Before, a drain ran until SIGKILL and a second signal did nothing.

**Consumer adjustment** -- none for an app whose drain fits its grace. An app that raises `terminationGracePeriodSeconds` through chart values sets `shutdown.drain_deadline_secs` to match, and one that must wait out any drain sets it to 0.

## A Kafka consumer rebuild 5 minutes after the last starts a new run (BEHAVIOUR CHANGE)

A fatal rebuild 5 minutes or more after the previous one keeps readiness and waits no backoff. Before, two fatals hours apart on a quiet topic counted as consecutive, so the second failed readiness until a record arrived.

**Consumer adjustment** -- none.

## Kafka holds acknowledged offsets as ranges (BEHAVIOUR CHANGE)

Held offsets are stored as ranges, not one entry per record. An hour at 10k records/s on one partition costs about 500 KB, down from about 25 B a record. `transport_ack_held_bytes` counts a partly released range as its unreleased share of the range's bytes.

**Consumer adjustment** -- none. A file roll shortened to save memory while offsets are held can go back to an hour.

## HTTP source holds its answer until delivery (BEHAVIOUR CHANGE)

With a `<key>.http.acknowledgements` section and built armed (`from_config_armed`, or `HttpTransport::builder(..).acknowledgements(..).armed(true)`), a POST gets 200 only once every record is delivered, dropped or dead-lettered. Otherwise it gets 503 with `Retry-After: 1`, as it does past `max_hold_ms` (25000) or at `max_held_bytes` (256 MiB). Without a section it answers at enqueue, and `pipeline_delivery_guarantee` reads `acks_disabled`.

**Consumer adjustment** -- `HttpTransportConfig` literals add the two fields or end in `..Default::default()`. A sender's timeout must exceed `max_hold_ms`.

## File source saves its position only past delivered lines (BEHAVIOUR CHANGE)

With a `<key>.file.acknowledgements` section, the `.pos` sidecar advances only past lines that are delivered, in file order. On Unix it reads `<offset> <dev>:<ino>` and the reader follows a rotation.

**Consumer adjustment** -- none without the section. With it, an older release reads the new sidecar as offset 0.

## A File source waits at the end of the file (BEHAVIOUR CHANGE)

`FileTransportConfig` gains `recv_timeout_ms`, default 100. At EOF `recv` reads again every 10 ms until a line arrives or the timeout passes, then returns empty. A pipeline over a file source no longer spins, and `close()` can wait up to the timeout for a `recv` in progress.

**Consumer adjustment** -- a struct literal adds the field or ends in `..Default::default()`. Set 0 for the old return-at-once.

## Pipeline process runs off the runtime worker (BEHAVIOUR CHANGE)

The pipeline, `run_workbatch`, `run_workbatch_parsed`, `run_governed` and `run_workbatch_streaming` call `process` through `tokio::task::block_in_place` on a multi-thread runtime. A slow or blocking `process` no longer stalls the other tasks on that worker. A current-thread runtime runs it inline, as before. Two pipelines joined in one task with `tokio::join!` still share a thread, so each waits on the other's `process`.

**Consumer adjustment** -- none.

## scalo-service takes a platform's env in `integrationEnv` (API CHANGE)

`integrationEnv` is a values map of the same shape as `extraEnv`, for env a platform sets for an integration. It renders after `extraEnv`, and `extraEnv` wins a name both set, so an overlay can replace a platform value. The chart's derived names still win over both, except `OPENSSL_CONF`, which either map can set. Each name renders once.

**Consumer adjustment** -- none for a chart that sets only `extraEnv`. A platform that writes integration values into `extraEnv` moves them to `integrationEnv`, so an overlay's `extraEnv` can replace them.

## SharedConfig::snapshot reads the version with its config (API and BEHAVIOUR CHANGE)

`SharedConfig::snapshot()` returns `(u64, T)`, the version and a clone of the config, read under one lock. `update()` bumps the version and sends the watch value before it releases the write lock.

**Consumer adjustment** -- a caller that read `version()` then `get()` to pair them calls `snapshot()` instead. Existing accessors keep their signatures.

## ObservingActuator removes its health component on drop (BEHAVIOUR CHANGE)

With the `health` feature, an actuator holds its `self_regulation:<source>` registration. Dropping it removes the component from `/readyz`. Before, each rebuild left the old component registered.

**Consumer adjustment** -- none for a gate built once. A check that counted stale components reads one per source after a rebuild.

## Idle series timeout (API CHANGE)

`MetricsConfig` gains `idle_timeout: Option<Duration>` and `MetricsSettings` gains `idle_timeout_secs`. Unset, nothing changes. With it set, counters and histograms idle past the timeout leave `/metrics` and come back from zero on their next write, held handles included. Each counter or histogram write costs about 80 ns more.

**Consumer adjustment** -- a `MetricsConfig` struct literal adds `idle_timeout: None` or ends in `..Default::default()`.

## UsageMetrics counts usage_ingested_bytes_total per org (API CHANGE)

`scalo::metrics::groups::UsageMetrics` has `record(&self, org, bytes)`, which counts `usage_ingested_bytes_total{org_id}`. The manifest describes it under the group `usage`.

**Consumer adjustment** -- enable `service-metrics`, which implies `metrics`. Delete the app's own copy of the series and its manifest description, and call `UsageMetrics.record(org, bytes)` once per org for each batch that settles as taken.

## The contract gains a `memory` block and `bench-memory` (API CHANGE)

`DeploymentContract` gains `memory: Option<MemoryProfile>`, left out of the JSON while `None`. `StandardCommand` gains `BenchMemory`, and `generate-artefacts` gains `--memory-profile`. The `bench-memory` feature adds `ServiceApp::bench_pipeline` (default `None`) and `cli::BenchPipeline`. `generate-artefacts` rejects a contract that sets `memory` in code.

**Consumer adjustment** -- a contract written field by field adds `memory: None`, and an exhaustive `match` on `StandardCommand` adds `BenchMemory(_)`. To publish figures, enable `bench-memory`, implement `bench_pipeline`, run `bench-memory --output ci/memory-profile.json`, then `generate-artefacts --memory-profile ci/memory-profile.json`.

## App-level TLS profile defaults (API CHANGE)

`scalo::crypto::TlsProfiles::set_app_default` sets, once per process, the settings a site's `tls.profiles` section falls back to. A site's section still wins for each profile it sets, and a profile it leaves out keeps the app's setting. A second call returns `AppDefaultError::AlreadySet`. Without a call nothing changes.

**Consumer adjustment** -- none required. An app that wants TLS 1.2 on `strong` everywhere calls `TlsProfiles::set_app_default(TlsProfiles::default().with_tls12(CryptoProfile::Strong, true))` once in `main`, before any TLS config is built.

## The TLS 1.2 warning repeats once an hour (BEHAVIOUR CHANGE)

A TLS 1.2 handshake logs its warning once an hour for each side and profile, where it logged on every handshake. `tls_tls12_handshakes_total` still counts every one.

**Consumer adjustment** -- none.
