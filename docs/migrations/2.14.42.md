# Migrations: 2.14.42

API and behaviour changes in 2.14.42 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## scalo-service spreads pods across nodes by default (BEHAVIOUR CHANGE)

With `affinity` unset, a workload that can run more than one pod renders a preferred pod anti-affinity on `kubernetes.io/hostname`, weight 100, over the selector labels. More than one pod means a `replicaCount` above 1, KEDA on, or the fallback HPA on. A singleton and a single fixed replica render none. Preferred, so a single-node cluster still schedules every replica.

**Consumer adjustment** -- none for most apps: the next rebuild renders the default. A deployer that wants no anti-affinity sets `affinity` to any other non-empty value, which replaces the default outright. A chart that silenced kube-linter's `no-anti-affinity` check can drop the annotation.
