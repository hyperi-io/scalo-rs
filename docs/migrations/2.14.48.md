# Migrations: 2.14.48

API and behaviour changes in 2.14.48 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## Deadlines are `tokio::time::Instant` (API CHANGE)

Every public deadline now uses Tokio's clock instead of `std::time::Instant`, so a test on a paused clock (`#[tokio::test(start_paused = true)]` with `tokio::time::advance`) moves it. A std deadline never passed under a paused clock, because each attempt worked out the time left from the system clock.

The changed signatures:

- `TransportSender::send_batch_by(&self, records: &[Record], deadline: tokio::time::Instant)`, and `DynTransportSender::dyn_send_batch_by` to match.
- `TransportReceiver::hold_deadline(&self, tokens: &[Self::Token]) -> Option<tokio::time::Instant>`.
- `Tickets::admit(&self, bytes: u64, deadline: tokio::time::Instant)` and `Ticket::deadline(&self) -> tokio::time::Instant`.
- `HeldAcks::earliest_deadline: Option<tokio::time::Instant>`, and the matching argument of `HeldAcks::new`.

**Consumer adjustment** -- build a deadline with `tokio::time::Instant::now() + timeout`, or convert one you hold with `tokio::time::Instant::from_std(deadline)`. An implementor of `TransportSender` that overrides `send_batch_by`, or of `TransportReceiver` that overrides `hold_deadline`, changes its signature to match and drops any `from_std` it did inside. Outside a Tokio runtime the Tokio clock reads the system clock, so sync callers keep working.
