# Migrations: 2.14.46

API and behaviour changes in 2.14.46 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## Kafka ssl_skip_verify is removed (API and BEHAVIOUR CHANGE)

`KafkaConfig.ssl_skip_verify` used to turn TLS certificate verification off, refused only in production. The key now fails the load in every environment, naming `tls.ca_paths`. `with_ssl_skip_verify()` and `with_ssl_insecure()` are gone, and `devtest()`, `for_testing()` and the `devtest` profile no longer turn verification off. `{PREFIX}_SSL_SKIP_VERIFY` and its `SSL_INSECURE` and `INSECURE` aliases are warned of and ignored, so certificates are verified.

**Consumer adjustment** -- drop `ssl_skip_verify` from configs and struct literals, and drop calls to the two builders. Trust a private or self-signed broker CA with `tls.ca_paths` (or `{PREFIX}_SSL_CA_LOCATION`). A dev-only setup that must skip verification sets `enable.ssl.certificate.verification: "false"` in `librdkafka_overrides`, which production still refuses.

## Generated runtime images run on ubuntu:26.04 (BEHAVIOUR CHANGE)

`DEFAULT_BASE_IMAGE` is `ubuntu:26.04` (glibc 2.43) pinned by digest, in place of `debian:trixie-slim` (glibc 2.41), and `DEFAULT_BASE_DISTRO` is `BaseDistro::Resolute`. A regenerated Dockerfile's runtime stage starts from it and installs resolute's package names.

**Consumer adjustment** -- regenerate the Dockerfile and rebuild. An app that sets `deployment.base_image` keeps its own base. A binary must be built against glibc 2.43 or older.
