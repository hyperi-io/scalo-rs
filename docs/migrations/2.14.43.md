# Migrations: 2.14.43

API and behaviour changes in 2.14.43 that need a consumer adjustment. Older releases are in [migrations.md](../migrations.md) and this folder.

## A CEL rule under cel_on_error: match acts on MsgPack (BEHAVIOUR CHANGE)

A CEL filter with `cel_on_error: match` used to pass a payload whose first byte looks like MsgPack without reading it, on both the filter and dead-letter paths. It now takes the rule's action, so a drop rule drops it and a DLQ rule dead-letters it. The dead-letter path counts `transport_filter_msgpack_bypass_total` when it takes one.

**Consumer adjustment** -- none, unless an allow-list relied on MsgPack passing through. Such a list sets `cel_on_error: pass` to keep the old behaviour.

## SharedConfig::update notifies after the write lock (BEHAVIOUR CHANGE)

In 2.14.42 `update()` sent the watch value while it held the write lock, so a subscriber reading the config while holding `rx.borrow()` deadlocked with it. `update()` now sends after the lock drops. When two updates race, the channel keeps the higher version. `snapshot()` still pairs a config with its own version.

**Consumer adjustment** -- none.
